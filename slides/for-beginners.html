Claude Code と
Spec Kit の仕組み

専門用語を使わず、比喩で分かる「AI と正しく仕事をする方法」

所要時間: 約10分

対象: AI に触れたことはあるが、Claude Code や Spec Kit は初めての人

最終更新: 2026-07-26

「AI に頼んだら、
なんか違うものができた」

こういう経験、ありませんか？

😅 よくある失敗

  • 「○○して」と頼んだら別のことをされた
  • やってはいけないことをやられた
  • 長い説明を読まないで推測された
  • 設定がバラバラで AI が迷子になる

🙂 理想の状態

  • 目的を取り違えない
  • 禁止事項を守る
  • 次の一手が分かっている
  • 設定が一貫している

この「取り違え」を防ぐ仕組みが Claude Code と Spec Kit です。

Claude Code とは

AI に「この仕事場のルール」を常時読み込ませておく仕組み。AI がルールを忘れずに仕事をしてくれる。

比喩：新しいアルバイトさん

新しいアルバイトさんが来たとき、毎回「冷蔵庫はここ、手を洗ってから、エプロン着用」と教えるのは大変ですよね。

Claude Code は「いつでも見返せるルールブック」を AI に渡しておく仕組みです。

公式: code.claude.com

「ルールブック」の中身

実は1冊ではなく、目的別に7つのパーツがあります

📄 CLAUDE.md

常に効く基本ルール

🎓 Skills

必要な時だけ読むマニュアル

🚨 Hooks

絶対に守る禁止事項

🤖 Subagents

専門作業を任せる助手

🔌 MCP

外部システムへの接続

📦 Plugins

上記をまとめて配布

これらを総称して「ハーネス（harness = 装具）」と呼びます。

「誰の許可で動くか」も大事

AI が勝手にファイルを消さないよう、「何を自動でやっていいか」を段階的に設定します。

6つの許可モード

default（毎回聞く） acceptEdits（編集は自動） plan（読むだけ） auto（分類器で判断） dontAsk（CI 用） bypass（隔離環境のみ）

さらに「個人の設定」「チームの設定」「管理者の設定」の3段階があり、「ダメ」は常に優先されます。

Spec Kit とは

AI と一緒に仕事するときの「作業手順書のテンプレ」。GitHub 公式。

従来は「コードが王様」でした。Spec Kit は「指示書が王様、コードはそこから生まれる」という発想の転換です。

公式: github.com/github/spec-kit (v0.12.5, 2026-07)

Spec Kit の9つの手順

指示書を段階的に詰めて、最後にコードを生む

  1. Constitution — プロジェクトの絶対原則
  2. Specify — 何を作るか書く
  3. Clarify — 曖昧さを質問で潰す
  4. Plan — どう作るか決める
  5. Checklist — 抜けがないか確認
  6. Tasks — 細かい作業に分ける
  7. Analyze — 全体の整合性を見る
  8. Implement — コードを書く
  9. Converge — 指示と結果が一致したか確認

何が変わるか

😅 従来

  • README を人力で書く
  • ルールが口伝え
  • AI に毎回説明
  • 「あれ、こうだったっけ？」が多い

🙂 この仕組み

  • 意味ブロックから自動生成
  • ルールがファイルで永続
  • AI が常に最新ルールを参照
  • 取り違えが起きにくい

まとめ

  1. Claude Code は AI にルールを常時読ませる仕組み
  2. ルールは7つのパーツ（ハーネス）から成る
  3. 「誰の許可で動くか」も段階的に設定できる
  4. Spec Kit は指示書ファーストの作業手順
  5. 2つを組み合わせると、AI の取り違えを構造的に防げる
  6. 人間は要点を伝えるだけ。後は AI が走る
