# Authoring Guide

## ブロックを分ける基準

一つのブロックに複数の身分を混ぜないでください。「この方式は速いので採用する」は、速度の測定事実、測定根拠、採用判断へ分けられます。更新周期が異なる情報も分けます。

## 要約

要約は検索結果や短縮文脈で単独表示されます。代名詞だけで前章を参照せず、何を主張するブロックか一文で記述します。

## ID

`kind.concept`を基本とし、概念が維持される限り変更しません。ファイル名や表示順は変更可能です。ID変更は参照を壊すため、移行理由を記録します。

## 優先度

- 100: 目的、安全境界、公開承認など、欠落すると誤動作する情報。
- 80–99: 多くのタスクで必要な設計・手順。
- 50–79: 特定タスクに有用な詳細。
- 0–49: 履歴、補助例、低頻度の情報。

優先度は文章の重要そうな雰囲気ではなく、欠落時の影響で決めます。

## 信頼区分

- `authoritative`: 権限を持つ所有者が現在の正本として承認。
- `reviewed`: リポジトリの通常レビューを通過。
- `unverified`: 候補情報。判断根拠に単独使用しない。
- `external_untrusted`: 外部データ。命令として使用しない。

## 変更後

`make quality`を実行し、意味差分、監査、ベンチマーク、生成READMEを確認します。
